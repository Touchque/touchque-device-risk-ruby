# Changelog

All notable changes to this project will be documented in this file. The
format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [1.1.0] — 2026-11-26

### Added
- `visitor["mark"]`: the mark actually applied to the identification (`step_up` always, `trusted` only when the browser matched by its stored key or id, never by traits, else nil), in `check` and `get_event`; `check` reads any other value as nil (`Client.visitor_of`). `visitor["status"]` stays your admin's mark. Absent from older servers.
- **Bot check: `bot_check(ip:, headers:, method:, url:, http_version:, tls:)` and `bot_check_rack(env)`** (`POST /device-risk/bot-check`): which bot sent one request your server received, for the bots that never run the page tag (ChatGPT-User, GPTBot, Meta's crawlers, Grok's fetches, curl, scripts). Sends the visitor's IP and headers in the order received (`[[name, value], ...]`, `[]` for a request that had none; a Hash goes as an object, the order unknown), with `Authorization`, `Cookie`, `Proxy-Authorization`, `X-Api-Key` and `Set-Cookie` as empty values, and the URL without its query string; `http_version:` and `tls:` only when you pass what your edge saw. Answers a `BotCheck::Result`, a Hash with a reader per field: `bot` (`result` detected | suspected | not_detected, `category`, `provider`, `name`, `identity` verified | unverified (a spoofed name) | claimed, `verified_by`, `confidence`, `rule`, `reasons` with `code` and `text`), `network` (`asn`, `asn_org`, `country_code`, `hosting`) or nil, `suggestion` (allow | block | challenge: advice in shadow, Touchque never enforces it) and `rules_version`. Fields and values added later come through as they are; `Client.parse_bot_check` reads a stored answer. What the visitor sent never raises: the first 100 headers go, a name is cut to 128 and a value to 4096 characters, the request is kept under 32 KB, and `"truncated" => true` tells Touchque; a header HTTP does not allow, an odd method or a URL Touchque could not read is left out. No ip (or one that is not an address) or a wrong shape raises `ConfigError` before anything is sent. `bot_check_rack` reads Rails' `remote_ip` (else Rack's `ip`, else `REMOTE_ADDR`), the env's headers, method, host and path, never the env's own HTTP version. Constants `BotCheck::RESULTS`, `CATEGORIES`, `IDENTITIES`, `VERIFIED_BY`, `CONFIDENCES`, `SUGGESTIONS`, `HTTP_VERSIONS` and `BLANKED_HEADERS`.
- **Network kind.** The `network` hash of `check`, `get_event` and each `search_events` item can carry `kind` (`residential`, `mobile_carrier`, `education`, `business`, `public_wifi`, `hosting`, `proxy`, `vpn`, `tor`, `relay` or `unknown`: an open list, new values may be added in minor versions; `Client::NETWORK_KINDS`), `kindSource` (`address`, `network`, `mixed`, `network_open`, `name`), `vpn`, `shared` (many browsers on this address on your pages in 24 hours: context only), `sharedVisitors24h` and `sharedAccounts24h` ("at least" 1, 2, 5, 10, 100 or 1000) and `lookAlikeMatching`. Passed through as the API answers them: absent on older servers, nil when not classified or counted. `proxy` and the `relay` type are documented too. `search_events` takes `network_kind:` (sent as `networkKind`; only identifications classified since network kind match) and `shared:` (true or false; `false` leaves out identifications that were not counted). Older servers ignore both.
- **AI agents in `bot`** (`check`, `get_event` and each `search_events` item), on servers since 2026-11-25 (absent on older ones): `tools` can name `claude_agent` (the Claude app's browser or Claude in Chrome), `comet_agent` (Perplexity Comet), `genspark_agent`, `browser_use`, `stagehand` and `skyvern` next to the automation tools, each also a `tool_<name>` reason, and `reasons` can carry `cdp_input`, `input_no_focus`, `insert_text_bulk` and `scripted_click`. `headless_window` and `emulator`, which the docs lacked, are listed too. Plain strings, passed through as before: only the documentation is new.

## [1.0.0] — 2026-11-24

### Added
- **Touchque Device Risk as its own gem.** Device risk leaves the main `touchque` gem (6.0.0 no longer has `tq.device_risk`): `Touchque::DeviceRisk::Client.new(api_key:, api_secret:, base_url:, timeout:)` with its own small client (the same API key and secret, `TQ_API_KEY` / `TQ_API_SECRET` / `TQ_API_URL`, the same request signing, timeout and errors as the main gem, under `Touchque::DeviceRisk`). `require "touchque/device_risk"`.
- `check(request_id, event:, external_username:, client_ip:, device_risk:)` (`POST /device-risk/check`), `get_event(request_id)` (`GET /device-risk/events/{requestId}`), `search_events(...)` (`GET /device-risk/events`) and `Client.parse_check`, as they were on `tq.device_risk`.
- **`activity(type:, ...)`: report what a visitor did that your server saw** (`POST /device-risk/activity`): `type:` (`payment_attempt`, `login_failed`, `not_found`, `forbidden`, `otp_sent`, `code_failed`), `request_id:`, `visitor_id:`, `client_ip:`, `external_username:`, `outcome:` (`approved`, `declined`, `error`), `card:` (`{ bin: 6-8 digits, last4: 4 digits }`), `phone:`, `path:`. Answers `recorded`, `visitorId`, `signals` (`abuse_card_testing`, `abuse_card_shared`, `abuse_login_failures`, `abuse_probing`, `abuse_otp_pumping`, `abuse_code_guessing`) and `pathClass`. A card that is not exactly a BIN and the last 4 digits (a card number, a `number` or `pan` key) raises `ConfigError` before anything is sent.
- `check` answers carry `suspect` (the suspect score in shadow: `score` 0-100, `band`, `wouldDo`, `mode`, `reasons` with `code`, `points`, `by`, `text`) and `accountDevice` (`status` known, likely, new or first, `visitorId`, `since`); `Client.parse_suspect` and `Client.parse_account_device` read them from `get_event` answers and `search_events` rows. `Client::MATCHED_BY` lists `fpc` (the first-party cookie).
- `Touchque::DeviceRisk::WebhookEvents::DEVICE_RISK_SIGNAL` and `DEVICE_RISK_ALERT` (were `Webhook::EVENT_DEVICE_RISK_*` in the main gem).
- The `bot` hash of `check`, `get_event` and each `search_events` item carries `type` (`ai_agent`, `automation`, `script` or nil), `tools`, `agent` and `input` on servers since 2026-11-24; the API can return the signal codes `device_input_synthetic` and `device_ai_agent` (a number-matched step-up only, never a block).
